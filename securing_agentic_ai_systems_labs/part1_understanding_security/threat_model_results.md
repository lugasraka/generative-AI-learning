## Threat Model: Customer Support Bot

**Purpose:** Handles customer inquiries, looks up orders, issues refunds, and escalates complex cases to human agents.

### Tools / APIs

- `order_lookup_api`
- `refund_processing_api`
- `knowledge_base_search`
- `email_send`
- `ticketing_system`

### Data Access

| Read | Write |
|------|-------|
| customer_profiles | support_tickets |
| order_history | refund_records |
| knowledge_base | email_log |

### Autonomous Actions

- `issue_refunds_up_to_500`
- `send_emails_to_customers`
- `create_escalation_tickets`
- `lookup_order_status`

### Security Challenges

| Challenge | Rationale |
|-----------|-----------|
| Agents Act on Environment | Can trigger real financial transactions (refunds) and send communications (emails) without human approval. |
| Agents Chain Tools Dynamically | Chains order lookup → refund decision → email notification → ticket creation. |
| Agents Retain Memory Across Sessions | Retains customer interaction history across sessions to personalize support. |
| Agents Improvise and Adapt | Can improvise refund amounts and escalation paths based on conversation context. |

### Top Risks

| # | Severity | Risk | Controls |
|---|----------|------|----------|
| 1 | **CRITICAL** | Prompt injection causes unauthorized mass refunds to attacker-controlled accounts. | Human approval for refunds above threshold; rate-limit refund actions; log all financial actions |
| 2 | **HIGH** | Data exfiltration via crafted prompts that extract customer PII through the order lookup tool. | Field-level access control on order data; redact PII from LLM responses; monitor unusual access |
| 3 | **MEDIUM** | Memory poisoning inserts false customer preferences that persist across support sessions. | Expire cached preferences after TTL; validate memory updates against source of truth |

### Blast Radius

An attacker who injects a malicious prompt could issue refunds to arbitrary accounts, exfiltrate PII for thousands of customers, and poison memory so future sessions are compromised. Financial loss capped at ~$500/transaction but unlimited volume. Reputational damage from leaked customer data.

## Threat Model: Code Review Assistant

**Purpose:** Analyzes pull requests, suggests improvements, flags security issues, and can approve or request changes.

### Tools / APIs

- `git_clone`
- `static_analysis`
- `dependency_scanner`
- `pr_comment_api`
- `pr_approval_api`

### Data Access

| Read | Write |
|------|-------|
| source_code | pr_comments |
| git_history | pr_reviews |
| dependency_manifests | approval_decisions |
| security_advisories | |

### Autonomous Actions

- `comment_on_pr`
- `approve_pr`
- `request_changes`
- `flag_security_vulnerabilities`
- `suggest_code_fixes`

### Security Challenges

| Challenge | Rationale |
|-----------|-----------|
| Agents Act on Environment | Can approve PRs that merge to production, directly affecting codebase integrity. |
| Agents Chain Tools Dynamically | Chains clone → static analysis → dependency scan → review → approval in dynamic order. |
| Agents Retain Memory Across Sessions | Remembers past review decisions and code patterns across repositories. |
| Agents Improvise and Adapt | Improvises review strategies based on codebase size, language, and complexity. |

### Top Risks

| # | Severity | Risk | Controls |
|---|----------|------|----------|
| 1 | **CRITICAL** | Malicious PR crafted to trick the assistant into approving vulnerable or backdoored code. | Human sign-off for security-critical files; mandatory dual approval; sandbox code execution |
| 2 | **HIGH** | Prompt injection via code comments or variable names that manipulate review output. | Strip comments before LLM analysis; validate review output against static analysis; log full context |
| 3 | **MEDIUM** | Memory poisoning to skew future reviews in favor of attacker's code style or patterns. | Isolate memory per repository; periodically reset learned patterns; audit memory changes |

### Blast Radius

Compromised assistant could silently approve malicious code that reaches production, expose secrets found in source code, or systematically weaken security reviews for a targeted developer's PRs. Impact spans all repositories the assistant has access to.

## Threat Model: Financial Analysis Agent

**Purpose:** Pulls market data, runs analysis models, generates reports, and can execute trades within predefined limits.

### Tools / APIs

- `market_data_api`
- `portfolio_api`
- `trade_execution_api`
- `news_aggregator`
- `report_generator`

### Data Access

| Read | Write |
|------|-------|
| market_feeds | trade_orders |
| portfolio_positions | analysis_reports |
| trading_history | portfolio_adjustments |
| news_articles | |

### Autonomous Actions

- `execute_trades_within_limits`
- `generate_analysis_reports`
- `adjust_portfolio_allocations`
- `alert_on_market_events`

### Security Challenges

| Challenge | Rationale |
|-----------|-----------|
| Agents Act on Environment | Can execute real financial trades, moving actual money in live markets. |
| Agents Chain Tools Dynamically | Chains data ingestion → analysis → trade decision → execution → reporting. |
| Agents Retain Memory Across Sessions | Retains market analysis models and portfolio strategy preferences across sessions. |
| Agents Improvise and Adapt | Improvises trading strategies based on real-time market conditions and news. |

### Top Risks

| # | Severity | Risk | Controls |
|---|----------|------|----------|
| 1 | **CRITICAL** | Prompt injection triggers unauthorized trades or manipulates analysis to mislead investors. | Hard limit on trade size; human-in-the-loop for trades above threshold; real-time anomaly detection |
| 2 | **HIGH** | Data poisoning of news feeds influences analysis output and downstream trade decisions. | Cross-reference multiple news sources; flag articles from unverified sources; separate ingestion from decisions |
| 3 | **HIGH** | Memory poisoning alters portfolio strategy preferences, causing systematic misallocation. | Version-controlled strategy parameters; audit log for all memory mutations; periodic reconciliation |

### Blast Radius

An attacker could trigger trades that drain portfolio value, inject false analysis that misleads investors, or corrupt long-term strategy memory. Financial exposure limited by per-trade caps but aggregate losses could be severe. Regulatory reporting obligations may be triggered.

| System | Worst-Case Impact |
|--------|-------------------|
| Customer Support Bot | Mass unauthorized refunds, PII exfiltration, memory compromise. Financial + reputational damage. |

---

## Key Takeaway

Every agent system is vulnerable to all four security challenges, but the severity and blast radius depend on what the agent can do. Financial and code integrity systems have the highest blast radius. Defense requires layering controls: **guardrails**, **permissions**, and **auditability**.
